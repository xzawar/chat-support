# Baseline profile for com.codexce.supportchat
#
# WHAT THIS IS
#
# A list of methods that ART compiles ahead of time when the APK is installed, instead of
# interpreting them on the first launch and JIT-compiling them once they get hot. Cold start is
# the single worst case for interpretation: every class on the launch path is being touched for
# the very first time, so none of it has had a chance to get hot yet. Precompiling that path is
# worth roughly 30% off cold start, and it costs nothing at runtime.
#
# The androidx.profileinstaller dependency has been in this app for some time and has been doing
# absolutely nothing, because this file did not exist. AGP bundles src/main/baseline-prof.txt
# into the APK automatically - no Gradle plugin, no extra configuration.
#
# HOW TO REGENERATE IT
#
#   ./gradlew :benchmark:pixel6Api34BenchmarkAndroidTest \
#       -P android.testInstrumentationRunnerArguments.class=\
#          com.codexce.supportchat.benchmark.BaselineProfileGenerator
#
# then copy the generated profile over this file. Regenerate it whenever the startup path
# changes shape - a new screen before the inbox, a different splash, a change to which
# ViewModels are constructed at launch. A stale profile is not harmful, it is just progressively
# less useful, because the rules that no longer match are ignored.
#
# FORMAT
#
#   H  the method is called during startup ("hot")
#   S  the method is called from the startup path specifically
#   P  the method should be compiled ahead of time
#   L  a class rule rather than a method rule
#
# Wildcards are permitted in this human-readable form and are expanded at install time, so the
# broad rules below stay correct as classes are added.
